# 时间树累计节点山脊图

把一棵时间树的内部节点按样本分组摊开，估计各组**合并事件随时间的密度**，画成山脊图。
换一棵树 + 一张 metadata TSV，改 `conf/1-conf.yaml` 即可复用。

## 运行

```bash
bash pipe/1-pipe.sh                 # 用默认配置
bash pipe/1-pipe.sh conf/其他.yaml   # 指定配置
```

## 输入

放进 `input/`：

| 文件 | 要求 |
| --- | --- |
| 时间树 | **单棵** newick，枝长单位为年，超度量（ultrametric）。含多棵树会直接报错 |
| metadata | 制表符分隔，一行一个样本，含样本编号列与用于分组的类别列 |

树的 tip 名必须就是样本编号，与 metadata 的 `cohort.id_column` 列取值一致。
实际分析的样本是**两者的交集**：树上没有的 metadata 行、metadata 里没有的 tip 都会被跳过，
数量写在日志里。

## 脊线高度的两种口径

`conf` 的 `plot.height_mode` 决定同一面板内各条脊线怎么换算高度：

| 取值 | 高度含义 | 标尺 | 何时用 |
| --- | --- | --- | --- |
| `individual`（默认） | 每条脊线按自己的 5–95% 上界归一化，**高度不可横向比较** | 不画，改把每条自己的峰值写进左侧类别名（`peak = ...`） | 面板内峰高差距大时。差十几倍并不罕见，共用尺子会把矮的几条压成直线 |
| `shared` | 全面板共用一个换算系数，**高度真正可比** | 面板左上角一根单刻度竖线段 | 峰高量级接近，且正文需要直接比较高度时 |

`individual` 模式下 `ridge_scale` 不生效，改由 `ridge_scale_individual` 控制每条脊线占用的
行距；因为每条都会顶到该高度，它必须远小于 `ridge_scale`，否则类别一多脊线就彼此叠死。

不论哪种口径，纵轴的物理单位都是「每千名受抽样个体每千年的合并事件数」，
浅色带都是抽稀重复之间的 5–95% 区间，只反映抽稀，不含定年的后验不确定性。
用 `individual` 出的图，图注必须写明脊线是各自归一化的，否则读者会默认高度可比。
